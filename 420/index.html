Bounces that tell advisors what to do next

Campaign Report → Bounces today shows Bounce type and Sub-type with no explanation. These mocks put plain-language explainers and a next step on every bounce, give a one-click path to fix the subscriber without creating a duplicate, and block re-subscribing an address that already bounced.

The copy (same in every direction)

  1. Permanent · “Won’t be emailed again”: “Won’t be emailed again until you update the address. Edit this subscriber and change Status to Subscribed if you have a new email.”
  2. Transient / MailboxFull · “Inbox full”: “Temporary. We’ll try again next campaign. Their inbox may be full.”
  3. Transient / General · “Temporarily refused”: “Temporary refusal. Worth double-checking the address is still current.”
  4. 3rd temporary in a row · “Paused”: “Paused after 3 temporary bounces in a row, so it won’t get your next campaign. Check the address is still current. If you have a new one, edit this subscriber.”

No AWS/SES words. The raw type · sub-type stays in small grey text for support. Full mapping is in the build contract.

Why A:
  • An advisor learns “16 need a new address, the rest will sort themselves out” before reading a single row. B makes them read all 20.
  • Covers all four parts of the ask (explainers, per-row next step, one-click edit, summary banner) without C’s extra bulk-edit flow.
  • Front-end only: SESReports.jsx + the Edit Subscriber guard. No schema change. C’s Fix list can be added later on top of A.
