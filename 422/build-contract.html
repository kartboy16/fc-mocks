## Recommend: Direction A
Separate scoped workspace (`FsbContentLibrary` / own routes), FC chrome + **FSB partner** label, minimal nav (Library · Create · My advisors). New items go to an **FTT review queue** before FSB advisors see them. **Write-only in v1** (no schedule/send, no billing, no all-advisor MAP).

**Why not B first:** reusing full-admin `ContentLibrary.jsx` is inviting unless every `isAdminUserId` / `userRoles.isAdmin` call site is split. Today admin = see everything.

**Why not C first:** white-label + schedule expands the method surface (queues, tokens) before the partner can even author safely.

## Role definition
| Role | Who | Sees | Can |
|---|---|---|---|
| `admin` | FTT staff | All content, all advisors | Full admin (unchanged) |
| `admin-fsb` | FSB partner staff | Only HTMLPosts with source `fsb-content`; only advisors with that source on prefs | Create/edit (per open Q) own FSB content; list FSB advisors; **not** full admin |
| `advisor` | Advisors | Per existing visibility | Unchanged |
| `support` | Support | Existing support scopes | Unchanged — do not conflate with admin-fsb |

Ensure AdvisorSource document exists: name **FSB-Content**, slug **`fsb-content`** (`imports/collections/advisor_source.js` slugify).

Optional user field: `profile.fsbSourceId` or role-assignment scope pointing at that source id (do not trust client-supplied source on writes).

## Data model
- **HTMLPosts:** keep `advisorCategories[]` / `availableToAdvisorSourceIds`; for admin-fsb inserts server sets both to FSB-Content only. Reject client attempts to set another source.
- **Status (A):** e.g. `fsbReviewStatus: 'draft' | 'pending' | 'approved' | 'rejected'` (or reuse `isPublic` carefully — prefer explicit field so private library chrome stays clear). Approved → visible to advisors whose prefs include fsb-content (existing visibility OR).
- **AdvisorPreferences.advisorCategories:** FSB advisors already (or will be) tagged with that source id — same mechanism as today.
- **Users:** role `admin-fsb` via alanning:roles (+ user.roles array compat as today).

## Server-side enforcement (UI hiding ≠ security)

### Predicate helpers (new)
- `isAdminUserId` — **must remain** role `admin` only (`server/support-impersonation.js`).
- Add `isFsbAdminUserId(userId)` → role `admin-fsb`.
- Add `isFullOrFsbAdmin` only where intentional; never use for billing/MAP/global.
- `userRoles.isAdmin` must stay full-admin-only. Add `userRoles.isFsbAdmin` / `userRoles.hasRole('admin-fsb')` (hasRole already exists).
- `userRolesIncludeAdmin` / `userDocumentHasRole(..., 'admin')` in `imports/utils/userRoles.js` — do not treat admin-fsb as admin.

### Publications that must scope or deny admin-fsb
| Publication | File | Action for admin-fsb |
|---|---|---|
| `HTMLPosts` | `imports/server/publications.js` + `htmlPostsLibrary.js` | Query: only posts with FSB source id (not `{}` admin bypass) |
| `HTMLPostsByIds` | same | Same visibility; no admin bypass |
| `carouselHTMLPosts` | same | Scope via visibility context |
| `advisorSource` | `advisor_source.js` | Return only FSB-Content doc (today: any logged-in user gets all) |
| `allUsersBasic` | publications.js | Deny or return only advisors with fsb-content prefs (today: all advisors to any admin) |
| `emailTemplates` | publications.js | Deny, or templates owned/tagged FSB only |
| `contentThumbnails` / `contentMasters` `includePrivate` | publications.js | Deny private-all; admin-fsb ≠ `isAdminUser` |
| `socialPostQueue` / `advisorSocialTokens` / `advisorPostHistory` / `scheduledSocialPostsForAdvisor` | publications.js | Deny cross-advisor; if C later, only fsb-content advisors |
| `advisorConfigs` | publications.js | Already self-only — OK |
| `categories` / `masterCategories` | publications.js | Open Q: shared vs FSB-only; if shared, read-only OK |

### Methods that must scope, auto-set source, or deny
| Method area | File / pattern | Action |
|---|---|---|
| `HTMLPosts.create` / `update` / `updateContent` / email connect | `server/api/html-posts-api.js` (and collection methods) | Allow admin-fsb; **server-set** source to fsb-content; reject other sources; (A) force pending review |
| `HTMLPosts.get` | same | Only if in scope |
| `addAdvisorSource` / `updateAdvisorSource` / `removeAdvisorSource` | `advisor_source.js` | **Deny** admin-fsb (`ensureAdmin` today uses `userRoles.isAdmin` — keep it full-admin only) |
| `getAdvisorSources` / `getAdvisorSource*` | advisor_source.js | Scope to FSB or deny list-all (today: **no auth**) |
| `userRoles.addAdmin` / `getAllUsers` / approve/reject/revoke/delete | `server/user-methods.js` | **Deny** admin-fsb |
| `admin.*` | user-methods / admin-methods | **Deny** |
| Billing / Stripe | `server/stripe-billing.js`, firm billing UI | **Deny** |
| MAP / ManageAdvisorPosts bulk distribute | admin UI + related methods | **Deny** (C later: scoped schedule only) |
| Website publisher admin setup | `server/website-publisher/admin-access.js` `isAdminUser` | **Deny** admin-fsb |
| Images / media upload on behalf of any advisor | `server/user-methods.js` `targetAdvisorId` admin paths | Only fsb-content advisors if needed; else deny |

### Create flow (code today)
`imports/ui/admin/CreateHtmlPostPage.jsx` loads all `advisorSource`, lets multi-select Advisor Sources, calls `HTMLPosts.create` with `advisorCategories`. For admin-fsb: hide select, show locked chip; server overwrites categories/source ids.
