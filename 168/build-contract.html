# Build contract — Share destination picker (Direction A)

**Issue:** [kartboy16/content-library#168](https://github.com/kartboy16/content-library/issues/168)  
**Direction:** A — Checklist rows  
**Audience:** Software developer (staging build after mock approval)

## One-liner

Replace the Share combo dropdown with three independent checklist channels (Email · Social · Website); advisors multi-select any non-empty subset (or Select all), then Continue into existing per-channel draft/preview flows.

## Interaction rules

1. **Independent multi-select** — Email, Social, Website are separate toggles (checkbox rows). Any non-empty subset is valid (1, 2, or 3).
2. **Select all** — Text button above the list selects all three. When all three are on, the same control reads **Clear all** (or use optional **Clear** link).
3. **Continue gate** — Primary **Continue** is enabled only when `selectedCount ≥ 1`; otherwise disabled (grey / not-allowed).
4. **Cancel / close** — Cancel button, × close, **Escape**, and click outside (overlay) dismiss the picker without navigating.
5. **Empty guard** — If Continue is reached with zero channels (deep link / empty query), bounce to guard UI with link back to library (do not proceed into channel stubs).
6. **Keyboard** — Rows act as checkboxes (click / Space / Enter); Escape closes.

## Replace staging combo list (removed as primary UX)

These four **fixed combo** options must no longer be the primary Share control:

1. **Email full article** — Full article in email  
2. **Website and Social** — Publish to site, then share link  
3. **Website and Email** — Publish to site and email a teaser  
4. **Website, Social and Email** — Publish to site, share link, email teaser  

**After:** Three independent rows only. Combinations are produced by multi-select, not by named combo rows.

## States

| State | Behavior |
|-------|----------|
| Default | None selected; Continue disabled; count “0 of 3 selected” |
| Partial | 1 or 2 selected; Continue enabled; Clear visible (optional) |
| All | Via Select all or manual; count “3 of 3”; Select all → Clear all |
| Clear | Clears selection; returns to default |
| Closed | Picker dismissed; library unchanged |
| Summary | Chips for chosen channels; per-channel draft/preview stubs |
| Empty guard | No channels → message + back link |

## Acceptance mapping (issue AC)

- **AC-1:** Three independent options — Email, Social, Website (no combo list as primary)  
- **AC-2:** Any non-empty subset selectable  
- **AC-3:** Select all makes “all three” as easy as one  
- **AC-4:** Existing share flows still work per selected channel (mock shows stub cards with “Open draft” / “Preview”, not Send/Publish live)  
- **AC-5:** Scannable on mobile and desktop  
- **AC-6:** **Email-only → full article.** If the advisor selects **Email** and does **not** select **Website**, the email campaign must use the **full article** body (there is no website post to link to). Map the old staging combo **“Email full article”** → Email-only selection. When **Website is also selected**, keep today’s teaser + link-to-site email behavior.

### Email body mode (product rule)

| Selection | Email content |
|-----------|----------------|
| Email only | **Full article** in the email body (no site link required) |
| Email + Website (± Social) | **Teaser + link** to the site post (current Website+Email behavior) |
| Email + Social (no Website) | **Full article** (same as Email-only — no site link) |
