Today one dialog mixes settings for three ways to collect sign-ups: the embed, the hosted sign-up page and the new public subscribe API (your own form). Every form is all three at once, and nothing shows which setting belongs to which. This is a designer-first mock with generic sample data, FTT Mail only. Not agent-ready. Today (reference): today's screen rebuilt in its real order. A switch tags each setting with the type it affects and shows the problems found.

Earlier recommendation (not picked): C, a shared core with a panel for each way people sign up. Shared settings (list, tag, consent, double opt-in, interests, notify addresses, thank-you message, spam check) appear once. The embed, sign-up page and "my own form" panels can each be switched on, and each holds its own link or code. The allowed websites list sits above the panels and shows which ones use it. Borrow A's "How will you use this form?" question when creating a form, to decide which panels start on.

Options

  • PickedA. "How will you use this form?" first: pick Embed, Sign-up page or My own form, then see only those settings. Simplest to read, but one type per form, so using two ways means two forms. About 3–3.5 UI days.
  • Not pickedB. Tabs: Basics, Embed on website, Sign-up page, Your own form (API), Notifications. Each type has a "Use" switch. Shared settings sit on Basics, and the website list repeats on two tabs. About 3–3.5 UI days.
  • Not pickedC. Shared core plus a panel for each way (earlier recommendation): matches how forms really work (one form, several ways in). About 3–4 UI days.
