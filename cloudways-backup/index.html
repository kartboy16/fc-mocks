Cloudways backup and restore for FC-hosted advisor sites

Problem: advisors whose WordPress site we host on Cloudways can’t see when their site was last backed up or get it rolled back from FC, and staff have to do it by hand in the Cloudways dashboard.

These mocks add a Backups tab (this site only) to the advisor’s Website page, a staff console that lists sites one by one, and a guarded one-site restore flow, all based on what the Cloudways API really supports (see the build contract for the API mapping and sources). All data is fictional (Jane Advisor, Sam Support, Pat Admin, Your Firm Name, example-advisor.ca, Server 3). Every page has a Desktop / 390 toggle, or add &phone=1 to any link. Times are shown in PT.

This site only, in every option. Every backup and restore in these mocks is for one advisor site, for example example-advisor.ca. Restore example-advisor.ca only. Other sites on the server are not touched. FC uses only the one-site Cloudways calls: restore one site, back up one site, undo the last restore of one site. A restore can bring back this site’s files and database, files only or database only, and the last restore can be undone for 24 hours.

Risk: high. It changes live advisor sites and uses the Cloudways account token. FC’s Cloudways code still uses API v1 and the legacy API key, both past Cloudways’ end-of-life dates, so moving to API v2 comes first. Not agent-ready: Alex picks a direction.

Recommended: B. Advisors see their own site’s backups and can back up their own site, but a restore of their site is a request that support reviews and runs from a queue, like the #727 Website setup queue. A restore rewrites that one live site, including FC’s own WordPress connection, needs a disk-space check on the hosting server, and has only one 24-hour undo, so a person should press the button for now.

Directions

A. Advisor self-serve restore, with strong guards

This site only. The advisor restores their own site: pick a backup, see what will change, a fresh backup of this site first (locked on), type the site address, then restore with Undo for 24 hours. Fastest for the advisor, but it carries the most risk without a person checking.
