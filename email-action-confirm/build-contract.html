Build note

  1. GET and HEAD only render the page. So do OPTIONS and prefetch requests (Purpose/Sec-Purpose: prefetch). Nothing writes to the DB or Slack. Send Cache-Control: no-store, Referrer-Policy: no-referrer and X-Robots-Tag: noindex.
  2. The action is a POST from the button: a form post with the token in the body and a CSRF value tied to the rendered page, plus an Origin/Referer host check. Don't auto-submit. ?from=email only changes the layout (banner, sticky bar).
  3. Tokens are 32 or more random bytes, stored hashed in action_tokens (kind, targetId, advisorId, recipientEmail, expiresAt, usedAt, revokedAt).
  4. Each approver gets their own token. Every link in the email shares it.
  5. A token works once. A resend revokes the old one.
  6. The suggested default is 7 days. Unsubscribe tokens are per contact and don't expire (needs a compliance check).
  7. Idempotent: a repeat POST, or another approver's token after approval, shows already. Use a conditional update so approvedAt and the Slack post happen once.
  8. Record approvedVia: 'email-button', approvedAt, approvedBy, approvedIp (first X-Forwarded-For hop), approvedUserAgent and tokenId. Do the same for declines (declinedNote). Add the UA and method to the Slack line.
  9. Preview:
  10. Render the same HTML the send uses: buildWrappedCampaignEmailHtml, with the header and footer resolved as at send time.
  11. Show it in a sandboxed iframe (sandbox without scripts), with merge tags filled with sample values.
  12. No open pixel and no click-tracking rewrite. Links inside the preview don't work, and the unsubscribe link is dead.
  13. For social, use the queue item's text, image, networks and scheduledAt.
  14. If the content changes after the email went out, the page shows the current version. Saving after the approval email went out revokes the token and sends a new email (open question).
  15. Scanner GETs don't count. Log them as link_open (IP, UA, time) and keep one quiet line per campaign. Store the SES click IP, UA and timestamp from the SNS webhook.
  16. "To" line: reuse the recipientLine logic in ses-campaign-approval.js. Tags come first and read "Tag:" or "Tags:" with their names. Then listId gives "List: ". all_subscribers becomes "Audience: All contacts" (today it's "List: All subscribers"). If neither applies, leave the line out. The count is the same distinct-email query as today.
  17. Approval email template (SES and social): replace the action links with one "Review & approve" link to the B page (?from=email), or the variant Alex picks, add the summary block, the expiry date and the "nothing happens until you click" line.
  18. Unsubscribe:
  19. A GET shows the confirm page. The page button POSTs.
  20. The RFC 8058 one-click POST (List-Unsubscribe=One-Click, sent by Gmail and Yahoo) unsubscribes without CSRF or a confirm step and returns 200.
  21. Log source as one-click or confirm-page. Undo is a POST.
  22. In-app buttons, including #649 "Approve and Send in 1 hour", call the method or POST, never the GET URL.
  23. White-label: the unsubscribe page uses advisor branding only. Its URL host is still FC's (Meteor.absoluteUrl()).

Open questions

  1. How long should approval links last: 7 days (suggested, shown in the email), 72 hours, or until the send time?
  2. Once one approver approves, do the other approvers' links show "already"? (Suggested: yes.)
  3. Who gets the "Don't approve" or "Reject" note, and where does it show?
  4. Where should scanner-like opens go: one quiet Slack line per campaign, their own channel, or only the log?
  5. Should an expired link offer "Request a new link" (emails the same approver), or only Sign in?
  6. Unsubscribe tokens with no expiry, per contact: is that OK with compliance? (No CASL or CAN-SPAM conclusion is stated here.)
  7. The unsubscribe URL host is FC's domain. Is that OK for now, or should it be an advisor domain or a neutral host later?
  8. Should unsubscribe cover all of the advisor's emails, or one list? (The mock says all.)
  9. If the campaign or post is edited after the approval email goes out, should the old link be revoked and a new email sent, or should the page just show the latest version?
  10. Preview merge tags: sample values ("Hi {First name}") or the first recipient's real values?
