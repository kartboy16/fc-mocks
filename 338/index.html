Email Campaigns — labeled row actions

Five unlabeled icon actions per row make it easy to mis-tap trash vs duplicate. Advisors and assistants in their 50s–60s need plain-language actions and a clear scan path for name / status / date.

Provisional build contract · Markdown

Problem: Email Campaigns list packs five unlabeled icons (view / PDF / HTML / duplicate / delete) into each row. Narrow columns and small type make mis-taps likely — especially trash next to duplicate.
Soft Dev hold · Designer-first · not agent-ready. Mocks only. Do not wake Soft Dev. Do not mark agent-ready. Hold until Alex / Angelina lock a direction.
Acceptance criteria (cover in mocks)
  • AC-1: Destructive / secondary actions via a labeled control (menu or “More”) with plain words — not five unlabeled icons alone.
  • AC-2: Delete is visually and verbally distinct from Duplicate.
  • AC-3: Name / status / date stay readable; density does not force mis-taps.
  • AC-4: Clickable HTML mock + short build contract before Soft Dev.
Out of scope (this pass)
  • Send / schedule pipeline changes
  • Full Email Campaigns IA rewrite beyond row actions / scanability
  • Waking Soft Dev / marking agent-ready

Directions

RECOMMEND

A — More menu with plain words

Primary row keeps name / status / date. One labeled Actions (⋯) opens View, Download PDF, View HTML, Duplicate, Delete (danger). Clearest for 50s–60s; fewest mis-taps.

 ALT

B — Inline labeled buttons

Common actions as text buttons on the row; rare ones in More. Faster for power users; busier on narrow widths.

 ALT

C — View + More · demote empty columns

Primary View stays visible; rest in More. Shows how empty Compliance / Approval columns can hide to free scan space.

Provisional build contract (recommend A)

Row actions: labeled menu (not icon strip). Delete = danger styling + confirm. Scan path: name, status, date. Full text: build-contract.html.
