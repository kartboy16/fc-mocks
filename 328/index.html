Problem (CEO preference): Admins were using their Facebook (etc.) login and attaching the user’s company Page/token. Alex wants the advisor/user to use their own login to create the token. Mock: admins send an FC invite email so the user adds FB / LI / IG themselves.
Soft Dev hold · Idea / playground · not agent-ready. Designer-first mocks only. Do not wake Soft Dev. Do not mark agent-ready. CosB will ask Alex in #fc-bugs which direction to lock.
Hard rule — do not conflate with #237. Invite flow = user OAuth as themselves (their Meta/LI/IG login). FC “Admin as user” only prefills who to invite — it does not OAuth as the admin. Related #237 is Meta-all teaching for admin reconnect of shared tokens — different problem.
Acceptance (Alex feedback · admin-as-user)
  • When an admin is logged in as a user (FC impersonation), Invite opens with the recipient locked/prefilled to that advisor — no search required.
  • Optional “Invite a different user…” expands search; default remains autofill.
  • OAuth still runs as that user’s Meta/LI/IG login — not the admin’s account.
  • Top chrome shows Admin as user · [User · Firm] pill on admin screens.
